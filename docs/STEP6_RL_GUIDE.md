# Step 6 해설: GA + RL (강화학습으로 가치함수 보정)

> 이 문서는 v4를 만들 때 작성했다(당시 출발점은 v3). 최종 결과는 [`../results/README.md`](../results/README.md)를 본다.

> 대상: `src/rl_finetune.py` (MANUAL.md §8)
> 출발점: 현재 `agents/my_agent` = **v3** (GA 2회 학습)
> 이 문서의 수치 중 "직접 측정"이라고 적은 것은 v3 가중치로 실제로 돌려서 얻은 값이다.

---

## 0. 먼저 결론

**이 단계가 하는 일**

> v3의 점수 공식은 그대로 두고, 그 위에 **"이 배치 뒤에 앞으로 실제로 좋은 일이 일어났나?"를 경험으로 배운 보정값 V**를 더한다.
> 새 점수 = **GA 점수 + β × V**

**하면 어떻게 되나**

- 잘 되면, GA가 놓친 "당장은 괜찮아 보이지만 나중에 위험한 자리" 같은 걸 V가 잡아 줘서 v3보다 강해진다.
- 안 되면, v3와 비슷하거나 오히려 약해진다. 그래서 **반드시 v3와 맞대결해서 이길 때만 채택**한다.

**솔직한 예상**

- 제가 짧게 돌려 본 시험(라운드 3 × 12경기, β = 200)에서는 RL 후보가 v3에게 **34전 14승(41%)**으로, 나아지지 않았다. 데이터가 적은 시험이라 결론은 아니지만, **큰 기대보다는 "실험해 보고 결과를 발표하는 단계"로 생각하는 게 맞다.**
- 매뉴얼에 적었던 β = 5, 20, 50은 **너무 작아서 행동이 거의 안 바뀐다**는 것을 직접 측정으로 확인했다(§6). 이 문서에서는 β = 50, 200, 500을 추천한다.

## 1. 기초 용어

테트리스 예시와 함께 정리한다. 세미나 자료에 나온 용어는 ★ 표시.

| 용어 | 뜻 | 이 프로젝트에서 |
|---|---|---|
| 강화학습 (RL) ★ | 행동해 보고 받은 보상으로 더 좋은 행동을 배우는 방법 | 경기를 해 보고, 공격·승패 결과로 판단 기준을 고침 |
| 상태 (state) ★ | 지금 상황 | 보드, 현재·hold·next 조각 |
| 행동 (action) ★ | 에이전트가 고르는 것 | 조각을 놓을 자리 (회전, x, hold 여부) |
| 보상 (reward) ★ | 행동 직후 받는 점수 | 보낸 공격 1줄당 +0.05, 경기 끝에 승리 +1 / 패배 −1 |
| 에피소드 | 처음부터 끝까지 한 판 | 경기 한 판 |
| 정책 (policy, π) ★ | 상태 → 행동을 고르는 규칙 | "점수가 가장 높은 자리에 놓는다" |
| 탐욕적(greedy) 정책 ★ | 점수가 가장 높은 행동만 고르는 정책 | 배치 탐색의 기본 동작 |
| 탐험 / 활용, ε-greedy ★ | ε 확률로 무작위 행동(탐험), 나머지는 최선의 행동(활용) | 학습 중 5% 확률로 무작위 자리에 놓음 |
| 리턴 (return, G) | 지금부터 경기 끝까지 받는 보상의 (할인된) 합 | "이 배치 이후 앞으로 받을 보상 총합" |
| 할인율 (γ, 감마) | 먼 미래 보상을 얼마나 깎을지 (0\~1) | 0.98. 한 배치 뒤 보상은 0.98배, 두 배치 뒤는 0.98²배… |
| 가치함수 V ★ | 어떤 상태에서 앞으로 받을 리턴의 기대값 | "이 보드 모양이면 앞으로 얼마나 좋은 일이 있을까" |
| afterstate | 행동을 한 **직후**의 상태 | 조각을 놓고 줄까지 지운 뒤의 보드 |
| 특징 (feature) | 상태를 요약한 숫자들 | 구멍 수, 높이, 우물 등 11개 |
| 선형 함수 | 특징 × 가중치를 더한 것 | V = 기준값 + Σ θ × (표준화된 특징) |
| 회귀 (regression) | 입력으로 정답 숫자를 예측하도록 맞추는 것 | 특징 → 리턴 G를 맞추도록 θ를 계산 |
| ridge 회귀 | 가중치가 너무 커지지 않게 벌점을 준 회귀 | 데이터가 시끄러워도 안정적으로 θ를 구함 |
| 표준화 | (값 − 평균) ÷ 표준편차로 단위를 맞추는 것 | 구멍(0\~10)과 높이 합(0\~200)을 같은 눈금으로 |
| 몬테카를로 (MC) | 경기를 끝까지 해 보고 실제로 받은 리턴으로 배우는 방식 | 경기 후 G를 거꾸로 계산 |
| 정책 평가 ★ | 지금 정책이 얼마나 좋은지 V로 측정 | 수집한 경험으로 V를 맞추는 단계 |
| 정책 개선 ★ | V를 이용해 더 좋은 행동을 고르게 바꿈 | 새 점수 = GA + β·V 로 다시 선택 |
| 정책 반복 (GPI) ★ | 평가와 개선을 번갈아 반복 | 라운드를 5번 반복 |
| prior (사전 지식) | 학습 전에 이미 갖고 있는 판단 기준 | GA 점수 (v3 가중치) |
| β (베타) | 학습한 V를 얼마나 믿을지 | 0이면 v3 그대로, 클수록 V의 영향이 커짐 |

세미나 슬라이드 "Evaluation: π → V, Improvement: π → greedy(V)"의 그림이 이 단계에서 **그대로 코드로 구현**되어 있다.

## 2. GA만으로는 무엇이 부족한가

| | GA | RL (이 단계) |
|---|---|---|
| 무엇을 보고 배우나 | **경기 전체의 결과** (승률) | **배치 하나하나 이후에 실제로 일어난 일** |
| 배우는 것 | 기존 11개 가중치의 숫자 | 새 보정 함수 V |
| 질문 | "이 가중치 묶음이 전체적으로 더 이기나?" | "이런 모양의 보드를 만들면, 그 뒤에 공격을 보내고 이기는 경우가 많았나?" |

GA는 "어떤 배치가 좋았고 어떤 배치가 나빴는지"를 따로 구분하지 못한다. 한 경기에 수백 번 배치를 해도 결과는 승/패 하나로 뭉뚱그려진다. RL은 각 배치 이후의 실제 결과를 따로따로 기록해서 배운다. 이걸 **신용 할당(credit assignment)**이라고 한다. 어떤 결정이 결과에 기여했는지 나눠 주는 일이다.

## 3. 핵심 아이디어: GA 점수 + β × V

```text
            ┌───────────────────────────┐
후보 자리 ─▶│ 놓은 뒤 보드의 특징 11개   │
            └──────┬──────────────┬─────┘
                   │              │
          GA 가중치로 계산    학습한 V로 계산
          (v3의 판단)        (경험에서 배운 판단)
                   │              │
                   ▼              ▼
     점수 =   GA 점수    +   β ×  V
```

왜 V만 쓰지 않고 GA 점수에 **더하는가**?

- V는 적은 데이터로 배워서 불안정하다. V만 믿으면 v3보다 훨씬 약해질 수 있다.
- GA 점수는 이미 검증된 좋은 판단(prior)이다. V는 그 위에 **조금씩 보정**만 하게 한다.
- β로 보정의 세기를 조절한다. β = 0이면 v3와 완전히 같다.

## 4. 한 라운드에서 일어나는 일

`--rounds 5 --games 60` 기준. 이 과정을 5번 반복한다.

### ① 경험 수집

현재 정책(첫 라운드는 v3 그대로, 이후는 v3 + β·V)으로 60경기를 한다. 이때 Agent는 `ExploringAgent`라는 학습용 버전으로 바뀌어서 두 가지를 추가로 한다.

1. **탐험**: 5% 확률로 점수를 무시하고 무작위 자리에 놓는다. 항상 같은 판단만 하면 "다른 자리였다면 어땠을까"를 배울 수 없기 때문이다.
2. **기록**: 실제로 놓은 자리의 afterstate 특징 11개와, 그 시점까지 보낸 누적 공격량을 저장한다.

한 경기에 보통 수백 번 배치하므로, 60경기면 수만 개의 기록이 쌓인다.

### ② 보상 계산

경기가 끝나면 기록을 보고 배치마다 보상을 매긴다.

```text
배치 t의 보상 = 0.05 × (다음 배치 때까지 늘어난 공격 줄 수)
마지막 배치에는 추가로 +1 (승리) 또는 −1 (패배)
```

### ③ 리턴(G) 계산: 뒤에서부터 거꾸로

```text
G_t = 보상_t + 0.98 × G_(t+1)
```

예시로, 마지막 다섯 배치의 보상이 이렇다고 하자.

| 배치 | 보상 | G (뒤에서부터 계산) |
|---:|---:|---|
| 마지막 (승리) | +1.00 | 1.00 |
| 그 직전 | 0.00 | 0 + 0.98 × 1.00 = 0.98 |
| 2개 전 (2줄 공격) | +0.10 | 0.10 + 0.98 × 0.98 = 1.06 |
| 3개 전 | 0.00 | 0 + 0.98 × 1.06 = 1.04 |
| 4개 전 | 0.00 | 0 + 0.98 × 1.04 = 1.02 |

γ = 0.98이면 약 50배치쯤 뒤의 보상은 0.98⁵⁰ ≈ 0.36배로 줄어든다. 그래서 G는 대략 **"앞으로 수십 배치 동안의 공격량 + 경기 결과"**를 반영한다.

### ④ V 학습 (정책 평가)

모든 기록을 모아 **"특징 11개 → G"를 맞추는 선형 함수**를 ridge 회귀로 구한다.

```text
V(특징) = 기준값 + θ₁ × (착지높이 표준화) + θ₂ × (지운칸 표준화) + … + θ₁₁ × (줄수 표준화)
```

예를 들어 직접 측정한 결과(v3, 자기 자신과 6경기)에서 `holes`의 θ가 **−0.33**으로 가장 크게 나왔다. "구멍이 평균보다 많은 보드를 만들면, 그 뒤의 리턴이 낮았다"는 뜻이다. GA도 구멍을 싫어하지만, V는 **실제 결과로** 그걸 다시 확인하고 그 정도를 따로 정한다.

### ⑤ 정책 개선

새 V를 `model.json`에 저장하고, 다음 라운드는 **GA 점수 + β × 새 V**로 행동한다. 세미나의 "π → greedy(V)"가 이것이다.

### 저장되는 것

각 라운드마다 `round00_model.json` … `round04_model.json`이 생긴다. 내용은 v3의 `model.json`에 두 항목이 추가된 것이다.

```json
{
  "weights": { ... v3 가중치 그대로 ... },
  "use_hold": true,
  "value": {
    "bias": 0.19,
    "theta": [0.037, 0.0, -0.035, 0.184, -0.333, ...],
    "mean":  [ ... 특징별 평균 ... ],
    "std":   [ ... 특징별 표준편차 ... ]
  },
  "beta": 200
}
```

`agent_core.py`는 이미 이 형식을 읽을 수 있다. 그래서 이 파일을 Agent 폴더의 `model.json`으로 넣기만 하면 바로 RL 버전 Agent가 된다. 추론은 여전히 순수 Python이라 50ms 제한도 문제없다.

## 6. β는 얼마로 해야 하나 (직접 측정)

GA 점수는 후보끼리 수십 점씩 차이 나는데, V는 대부분 −1\~+1 사이 값이라 후보끼리 차이가 0.1 정도밖에 안 된다. 그래서 β가 작으면 V가 결정을 거의 못 바꾼다.

v3로 실제 경기 300배치를 두고, β에 따라 **v3와 다른 자리를 고른 비율**을 쟀다.

| β | 결정이 바뀐 비율 |
|---:|---:|
| 5 | 약 1% |
| 20 | 약 3% |
| 50 | 약 5\~6% |
| 200 | 약 16\~18% |
| 1000 | 약 38\~49% |

- β = 5, 20은 사실상 v3와 같다. 매뉴얼에 적었던 값은 너무 작았다.
- β = 1000은 절반 가까이 바꿔서 GA의 판단을 너무 많이 덮어쓴다.
- **추천: β = 50, 200, 500 세 가지를 비교한다.** 약하게, 중간, 강하게 보정하는 셈이다.

## 7. 학습 상대가 중요하다 (`--vs` 옵션)

원래 스크립트는 **룰베이스 두 개만** 상대로 경험을 모은다. 그런데 v3는 이 둘을 거의 항상 이긴다. 그러면 모든 경기가 "승리 +1"로 끝나서, V는 **"무엇이 패배로 이어지는지"를 배울 수 없다.** 결국 공격량만 예측하게 된다.

그래서 상대를 고를 수 있는 `--vs` 옵션을 추가하는 수정을 만들고, 제 환경에서 동작을 확인했다. 아래를 그대로 붙여 넣으면 `src/rl_finetune.py`가 자동으로 고쳐진다.

```bash
cd ~/projects/tetris-ai-agent
python - <<'EOF'
from pathlib import Path
p = Path("src/rl_finetune.py"); s = p.read_text(encoding="utf-8")
old_job = '''    result = match(me, load_rule_agent(opp), seed, seat)'''
new_job = '''    if opp.endswith(".json"):                 # model.json 경로면 내 Agent 구조로 상대 생성
        rival = PlacementAgent.from_json(opp)
    else:                                     # 이름이면 키트의 룰베이스
        rival = load_rule_agent(opp)
    result = match(me, rival, seed, seat)'''
old_arg = '''    ap.add_argument("--out", default=str(ROOT / "results" / "rl"))'''
new_arg = old_arg + '''
    ap.add_argument("--vs", nargs="+", default=list(OPPONENTS),
                    help="상대 목록: 룰베이스 이름 또는 model.json 경로 (예: agents/v1_hold/model.json)")'''
old_jobs = '''            jobs = [(model, OPPONENTS[i % 2], rng.randrange(10**6), (i // 2) % 2, args.epsilon)
                    for i in range(args.games)]'''
new_jobs = '''            jobs = [(model, args.vs[i % len(args.vs)], rng.randrange(10**6),
                     (i // len(args.vs)) % 2, args.epsilon)
                    for i in range(args.games)]'''
ok = all(x in s for x in (old_job, old_arg, old_jobs))
if ok:
    s = s.replace(old_job, new_job).replace(old_arg, new_arg).replace(old_jobs, new_jobs)
    p.write_text(s, encoding="utf-8")
print("patched" if ok else "FAILED: 원본과 다릅니다")
EOF
python -m py_compile src/rl_finetune.py && echo compile-ok
```

`patched`와 `compile-ok`가 나오면 성공이다.

이제 상대를 이렇게 섞을 수 있다.

| 상대 | 넣는 이유 |
|---|---|
| `agents/my_agent/model.json` (v3 자신) | 비슷한 실력이라 이기고 지는 경기가 섞임 → 패배 신호를 배움 |
| `agents/v1_hold/model.json` | 약간 약한 상대. 다른 스타일 |
| `dellacherie` | 기본 상대 |

참고로 직접 측정해 보니, 탐험(5% 무작위 배치)을 하는 v3는 탐험하지 않는 v3에게 **6전 6패**였다. 무작위 배치 5%만으로도 꽤 약해진다는 뜻이다. 그래서 학습 중 출력되는 `train_win_rate`가 낮게 나와도 정상이다. 실력은 반드시 탐험 없이 평가한다(§9).

| 옵션 | 뜻 |
|---|---|
| `--init` | 출발 모델 = v3 |
| `--vs` | 경험을 모을 상대 3명 (번갈아 가며) |
| `--rounds 5` | 평가 → 개선을 5번 반복 |
| `--games 60` | 라운드당 경기 수 (상대당 20경기) |
| `--beta` | V의 반영 세기 |
| `--epsilon` | 탐험 확률 (기본 0.05) |

**예상 시간**: v3끼리의 경기는 길어서(약 4,000\~5,500 tick) 경기당 시간이 GA 때보다 길다. β 하나당 5\~10분, 3개 합쳐 **20\~30분** 정도로 예상한다. GA처럼 첫 라운드 시간을 보고 다시 계산하면 된다.

### 출력 읽기

```text
[round 0] samples=21000 train_win_rate=0.35 -> round00_model.json
```

| 항목 | 뜻 |
|---|---|
| `samples` | V 학습에 쓴 배치 기록 수 |
| `train_win_rate` | 학습 중(탐험 포함) 승률. 실력 지표가 아님 |
| `round00_model.json` | 이 라운드의 결과 모델 |

## 10. 잘 안 될 수 있는 이유 (발표 때 분석 거리)

1. **데이터 대비 노이즈가 크다.** 테트리스는 조각 운이 크다. 같은 배치를 해도 이후 결과가 크게 달라서, 몬테카를로 리턴 G의 편차가 매우 크다.
2. **V가 단순하다.** 특징 11개의 선형 함수라, GA 가중치가 이미 표현하는 것과 크게 다르지 않을 수 있다.
3. **탐험 때문에 학습 정책과 실제 정책이 다르다.** V는 "5% 무작위로 놓는 Agent"의 가치를 배우는데, 실제 대전에서는 무작위로 놓지 않는다.
4. **라운드마다 V를 새로 맞춘다.** 이전 라운드 데이터는 버리기 때문에, 각 라운드의 데이터 양이 결과를 좌우한다.

### 더 키우고 싶다면 (시간이 남을 때)

- **데이터를 늘린다**: `--games 120`. 시간은 2배.
- **V를 키운다**: 선형 대신 작은 신경망(MLP)으로 학습하고, 가중치를 JSON으로 내보내 순수 Python으로 계산한다. 세미나의 DQN과 같은 방향이다.
- **TD 학습으로 바꾼다**: 경기 끝까지 기다리지 않고 "보상 + γ × 다음 V"를 목표로 학습한다. 노이즈가 줄어드는 대신, replay buffer와 target network가 필요해진다. 세미나 DQN 슬라이드의 내용이 바로 이것이다.

## 11. 발표에서 이렇게 설명하면 된다

> GA는 경기 전체의 승률로만 가중치를 고르기 때문에, 어떤 배치가 좋았고 어떤 배치가 나빴는지는 구분하지 못합니다. 그래서 강화학습으로 **배치 하나하나 이후에 실제로 얻은 공격량과 승패**를 기록하고, 놓은 뒤 보드의 특징으로 그 리턴을 예측하는 가치함수 V를 학습했습니다. 최종 점수는 **GA 점수 + β × V**로, 검증된 GA 판단을 prior로 두고 V가 보정하는 구조입니다. 경험 수집 → V 학습(정책 평가) → V를 반영한 행동(정책 개선)을 5라운드 반복했고, 이는 세미나에서 배운 정책 반복 구조와 같습니다.
>
> (결과) β에 따라 결정이 바뀌는 비율을 먼저 측정해서 β = 50, 200, 500을 골랐고, v3와의 맞대결 결과는 표와 같습니다.

효과가 없었다면 이렇게 덧붙이면 된다.

> 효과가 제한적이었던 이유는 테트리스 리턴의 노이즈가 크고, 선형 V가 GA 가중치와 표현력이 크게 다르지 않기 때문으로 분석했습니다.
